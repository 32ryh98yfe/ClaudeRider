# 주행 조작 v10 검증 기록

비교 기준은 `5db2299080399066cd2aa94cf9c8d49ff1e4a33a`의 물리 버전 9이며, 이 문서는 버전 10의 조작·충돌·종료·HUD 변경을 검증한 결과를 기록한다. 독립 형상 검사, 고정 입력 주행, 실제 브라우저 키보드 조작 및 저장 데이터 검증은 아래 범위에서 통과했다. **최종 소스를 고정한 441조건 경주 행렬, 전체 로컬 테스트와 14개 E2E까지 검증을 마쳤다.** 아래의 완료 표시는 이 로컬 검증 범위를 뜻한다. 원격 CI 상태는 [PR #1의 현재 HEAD 검사](https://github.com/32ryh98yfe/ClaudeRider/pull/1/checks)에서 확인하며, 원작 영상 속도 고증의 미충족 항목은 별도로 명시한다. 기계 판독용 요약은 [handling-v10-validation.json](./handling-v10-validation.json)에 있다.

이번 조정은 사용자가 요청한 감속과 제어 개선을 반영해 기준 카트 `pebble`의 일반 주행을 약 **174km/h**, 부스터 주행을 약 **197km/h**로 낮춘다. 월드 속도도 각각 28.9m/s, 32.591975m/s로 변경했으며, 기존 HUD 환산 계수 `205 / 34`는 유지했다. 정확한 표시 목표는 174.25km/h와 196.510437km/h다. 부스터 값은 모터의 추진 목표이므로 내리막·충돌 등 외력까지 제거하는 전역 속도 제한을 뜻하지 않는다.

이 속도 선택은 원본 영상의 절대 속도와 다르다. 원작의 동작 관계와 조작 연결은 계속 참고하되, **원본 영상의 절대 속도 오차는 진단값으로 공개하며 5% 고증 목표를 달성했다고 주장하지 않는다.** 이전 `fb71b3f` 기반 연구와 이 문서의 v9→v10 비교 기준을 혼용하지 않는다.

**입력과 조작 검증**

실제 키보드와 참조 재생은 같은 틱 입력 필터를 사용한다. 원시 전환의 타임스탬프·순서를 유지하고, 좌우 키가 겹치면 마지막으로 누른 방향이 우선한다. 같은 키의 자동 반복은 우선순위를 바꾸지 않는다. 한 틱에 Shift 요청을 최대 4개 처리하며 초과 요청은 다음 틱으로 이월한다. 브라우저 수신, 예측 입력, 권위 시뮬레이션 적용을 각각 기록했다.

**장애물과 지형 접촉 검증**

최종 `.ctrk`와 `.vis` 21쌍을 한 프로세스에서 검사했다. 컴파일러의 도로 여유 공간 판정 함수를 재사용하지 않고 별도 BVH 거리·선분/삼각형 스윕 검사로 원본 모델, 저장된 충돌 형상, 인스턴스 변환, 런타임 접촉 조회를 비교했다. 배경이라는 이유만으로 단단한 모델을 거리 기준으로 제외하지 않는다. 삼각형 정점만 검사하지 않고 지면 내부와 가장자리를 최대 0.75m 간격으로 확인했다.

삼각형 수는 트랙별 검사 누계이며 고유 모델 수와 다르다. 원본 단단한 형상의 단순화는 제거했고, 오차는 저장용 양자화에서 발생한다. 도로가 이미 나타내는 기초 부분과 수평 지지면은 실제 지면과의 위치 관계를 따로 증명한다. 풀·물·천·잎, 분기점 완충물, 도로 바깥 경계 접촉 등은 명시된 분류로 남긴다. 겹친 형상에서 출력 버퍼가 포화되면 버퍼를 늘려 해당 삼각형 접촉을 확인하므로, 깊은 접촉을 우선 반환하는 정상적인 제한을 누락으로 오판하지 않는다.

Token `s=238`, Sunset `s=134`, Manor `s=515.5,u=2`, Fernwood `s=659.5,u=2`의 기존 통과·끼임 재현점도 모두 통과했다. Belltower의 미세한 잘림 잔여물, Pumpkin의 뒤집힌 지면 삼각형, Magma의 레일 여유 공간 문제는 최종 파일에서 다시 검사했다. 이 결과는 형상 일치와 샘플 경로 검증이며, 연결된 경주 행렬을 대신하지 않으며, 아래에 별도의 최종 경주 결과를 기록한다.

동적 장애물은 실제 렌더러가 만든 메시를 공통 물리 자세에 놓고 검사했다. 32개 몸체, 142개 상태 시점, 236,034개 표시 정점이 물리 형상 안에 들어갔으며 최대 초과량은 4.77×10⁻⁸m였다. Magma의 세 금속 그레이팅은 68,700개 표면 샘플 모두 실제 지면에서 3.501mm 이내였다. 장식용 지지선은 명시된 유연한 케이블이며 폭·깊이가 14cm 이하여야 한다. 두꺼운 피스톤에 장식 이름만 붙이는 예외는 허용하지 않는다.

Kraken의 충격 연출은 단단한 철구와 솟은 링을 없애고 열린 물기둥, 분리된 거품, 평평한 물결 표시로 바꿨다. 접촉이 트리거인 표시 메시 12개 사례는 명시된 유체 역할, 투명도, 비금속 재질, 깊이 기록 해제를 함께 검사했다. 불투명하거나 금속인 몸체는 유체라는 이름만으로 검사를 통과하지 못한다. 증기·경고 원·그레이팅은 각각 다른 근거로 분류한다.

**종료, 저장 데이터와 HUD**

새 Chrome 컨텍스트에서 R9L 전체 p2p 코스를 실제 키로 완주했다. 시작 이후 월드 상태를 덮어쓰지 않았으며, 벽 접촉·리스폰은 0회였다. 691틱에 결승선을 통과한 뒤 가속을 계속 누르고 Shift·왼쪽·Ctrl을 추가했다. 820ms 뒤인 740틱에서 속도는 0이었고, 이후 관측한 86틱 동안 계속 0이었다. 완주 뒤 권위 서버가 적용한 130개 입력은 모두 중립이었다.

처리 결과 화면까지 개발용 세션의 `GhostRecorder`와 고스트 재생기는 없었고 IndexedDB 열기 횟수는 0이었다. `cr.save.v1` 전체가 주행 전후 동일했으며 기록·XP·보상도 바뀌지 않았다. 별도 일반 Meadow timeAttack은 기존 자동운전과 16배속으로 저장 경로를 확인했으며, 개발용 가드가 꺼진 상태에서 기록기·고스트 조회·PB·고스트 키·XP 저장이 모두 동작했다. 이 정상 모드 확인을 실제 키보드 완주 검증과 혼동하지 않는다.

HUD는 Meadow, 분기가 있는 Spark Grand Circuit, p2p인 Aurora Summit을 960×720(4:3), 1280×720(16:9)에서 확인했다. 총 6조건 모두 실제 코스가 표시됐다. 회로는 닫히고 Spark 분기와 Aurora 경로는 열려 있었으며 모든 경로가 같은 보기 영역에 들어갔다. 카트 마커와 월드 좌표의 최대 차이는 0.005063m로, SVG 좌표 반올림 범위였다. 이는 화면 픽셀 오차와 다른 값이다. 기존 저장값 `minimapInSpeed:false`는 코스 지도 기본값으로 이행되고, 사용자가 명시적으로 선택한 진행률 막대는 설정 변경과 새로고침 후에도 유지됐다. 두 화면비의 QA 및 종료 검증에서 브라우저 콘솔 오류는 0회였다.

원작/v9/v10 비교 영상은 결정론적 렌더링 재생이다. 물리 2틱마다 카메라를 1/30초 진행하고 한 프레임을 저장했다. 4구간×2버전의 1,536개 상태가 Node와 브라우저에서 같은 해시였고, 모든 캡처가 2틱 간격이었다. 두 버전은 같은 `reference` 카메라 프로필을 사용했다. 이 일치 검증은 렌더링 재생의 시뮬레이션 정확도이며, 원작 카메라의 차체 크기·위치·추종 지연을 모두 맞췄다는 증거는 아니다.

로컬 전달 영상은 `reference-v9-v10-comparison.mp4`(12.733초, 원작/v9/v10·키·속도 곡선), `R9L/realtime.webm`, `R9R/realtime.webm`, `R12L/realtime.webm`, `R12R/realtime.webm`, `R16L/realtime.webm`, `R16R/realtime.webm`이다. U자 주행 영상은 더 강한 횡그립을 채택한 후보에서 약 60fps로 촬영했다. 이후 충돌·AI·종료 가드 변경은 이 평지 무접촉 입력열의 조작 모델을 바꾸지 않는다. 원본 영상, 상세 프레임 로그, 비교 영상과 스크린샷은 로컬에 보관하고 Git에는 코드·주석·요약만 넣는다.

원본 비교의 v9 실행은 보존한 `5db2299` 체크아웃에서 같은 구간·초기 조건으로 수행한다. 서로 다른 트랙 전체 랩타임은 원본과 직접 비교하지 않는다. 영상 합성은 `tools/reference/compose.swift`를 사용하며 원본 파일은 로컬 경로로만 전달한다.

종료·저장 검증은 새 브라우저 컨텍스트에서 `/?go=1&track=proving_ring&mode=timeAttack&handling=R9L&renderer=webgl2&quality=low&laps=1`을 열어 재현한다. 가속을 유지하고 71틱에 왼쪽+Shift, 188틱에 Shift를 유지한 채 오른쪽, 204틱에 방향키·Shift를 해제한다. 완주까지 가속을 유지하고 결승선 뒤 Shift·방향·부스터를 입력한다. 0.8초 뒤 속도, 결과 화면의 저장값, `Session.isDevelopmentRun`, 기록기·고스트 상태와 IndexedDB 접근을 확인한다. 틱·입력 관측은 `window.__cr`의 입력 추적 인터페이스를 사용하고 월드 상태는 수정하지 않는다.

HUD는 위 세 트랙의 일반 speed 모드를 두 화면비로 실행하고 실제 SVG 경로·마커를 확인한다. 기존 저장값 이행과 설정의 진행률 막대 선택을 각각 확인한다. 이는 단위 테스트만으로 대체하지 않은 실제 화면 QA다.

전체 경주 행렬의 재현 명령은 다음과 같다. 21트랙×3시드×(3모드의 단독·8대 경주 + timeAttack 단독)으로 441조건이다. 아래 최종 집계는 동일한 소스와 트랙 파일로 완료한 결과다.

**최종 통합 검증 결과**

행렬 실행 전후 시뮬레이션·콘텐츠 소스 트리 SHA256은 모두 `4d39ce92f02974413a80c9473d241dd10b60e87993ff81cabdddea400b303263`였다. 결과의 `complete`와 `sourceStable`은 모두 참이며, 행렬의 21개 트랙 파일 해시도 독립 접촉 검사에서 사용한 파일과 일치했다. 로컬 전체 보고서 `matrix-release.json`의 파일 SHA256은 `9c08e740e528f432877275a5683598646c0ecb0514132ce1815a683efab4be86`다. 파일 해시와 소스 트리 해시는 다른 식별자다.

| 항목 | 기준 v9 | 최종 v10 |
|---|---:|---:|
| 경주 조건 완주 | 441 / 441 | 441 / 441 |
| 카트 완주 | 1,764 / 1,764 | 1,764 / 1,764 |
| 강한 충돌 | 47 | 47 |
| 리스폰 | 12 | **20** |
| 최대 진행 정체 | 407틱 | 198틱 (3.3초) |

최종 단독 주행과 비아이템 모드의 리스폰은 모두 0회다. 최종 20회는 전부 8대 아이템 경주에서 발생했다. 기준보다 **8회 늘어난 리스폰과 원시 비교 규칙이 표시한 11개 경고를 지우지 않고 유지**한다. 시나리오·슬롯·리스폰 틱의 20개 식별자가 독립 인과 검토와 정확히 일치했다. 18회는 아이템 공격 또는 공격 후 남은 감속·위치 영향, 2회는 별도의 카트 접촉이 원인이었다. 두 접촉 사례는 같은 스냅샷과 기록 입력에서 상대 카트를 제외하면 안전하게 착지하는 반사실 재생으로 확인했다. 설명되지 않은 사례는 0회다.

이는 모든 전투 손실이 불가피하다는 주장이 아니다. 트랙 해시와 아이템 획득 시점도 아이템 결과에 영향을 주므로 같은 공개 시드만으로 기준·후보의 전투 이력이 같아지지 않는다. 11개 원시 비교 경고는 검토를 마친 상태이며, 0개로 재분류하거나 비교 문턱을 완화하지 않았다. 경주 통과 결과와 리스폰 증가를 함께 판단해야 한다.

20개 사례별 분류·사건 순서·반사실 조건은 [아이템 리스폰 검토 요약](./item-respawn-v10-review.json)에 보관한다. [재현 도구](../../tools/reference/review-item-respawns.mjs)는 현재 소스와 행렬의 해시를 확인하고 실제 아이템 경주를 다시 실행해 시나리오·슬롯·틱을 대조한다. 상세 프레임 추적과 반사실 실행 결과는 지정한 로컬 출력 디렉터리에 저장한다. 기준 행렬의 수치도 함께 검증하려면 `--baseline`에 보존한 v9 행렬을 전달한다.

Racer의 최종 속도 배수는 0.95에서 **0.955**로 조정했다. 줄어든 부스터 우위 아래에서 난이도 간 상대 페이스를 유지하기 위한 명시적인 균형 조정이다. 0.95에서는 시드31·두 바퀴 Manor/Kraken 혼합 아이템 경주의 일부 카트가 계속 움직이는 중에도 결승선 근처에서 기존 600틱 은퇴 제한에 걸렸다. 0.955에서는 두 경주 모두 8/8 완주, 리스폰·강한 벽 충돌 0회였으며, 12개 캐릭터 평균 Racer 페이스 95.0%가 기존 92–96% 범위에 남았다. AI 페이스와 아이템 트랙 검사 **31/31**, 그중 혼합 Pro/Racer 아이템 트랙 21개 기준이 그대로 통과했다. Pro·Legend·플레이어 카트 성능과 은퇴 제한은 이 조정으로 바꾸지 않았다. 근거와 범위는 [연속 주행 설계](../design/19-continuous-handling.md)에 기록되어 있다.

| 최종 로컬 검사 | 결과 |
|---|---|
| 전체 테스트 | **1,042 통과 / 0 실패 / 기존 건너뜀 61**, 합계 1,103 |
| 형 검사 | **9개 프로젝트 통과** |
| 린트·의존성 경계·동결 계약·접촉 카탈로그 | 모두 통과 |

E2E는 Node·Chrome·Worker 결정론, 두 브라우저의 온라인 경주, 일반 timeAttack 고스트 저장·재생, 팀전, 메뉴·HUD 및 일시정지 후 새 입력을 포함한다. 61개 기존 건너뜀은 통과 수에 더하지 않았다. 상세 로그는 로컬의 `regression-release.json`, `e2e-release.log`에 남기고 Git에는 요약과 해시만 보관한다.

원격 CI의 상태 출처는 [PR #1 Checks](https://github.com/32ryh98yfe/ClaudeRider/pull/1/checks)다. 현재 PR HEAD와 실행의 HEAD SHA가 같은지 확인해야 하며, 과거 커밋의 통과를 현재 상태로 사용하지 않는다. 게시 시점의 정확한 커밋·실행 링크는 PR 메타데이터에 기록한다. 이 문서에 존재하지 않는 커밋 SHA나 영구적인 대기 상태를 넣지 않는다.

`handling-v10-validation.json`의 상태는 `local_acceptance_complete`이며, 완료 범위는 이 문서의 로컬 회귀·행동 검증이다. 원본 속도·카메라의 완전한 고증이나 현재 원격 CI 결과를 대신하는 표시는 아니다.
